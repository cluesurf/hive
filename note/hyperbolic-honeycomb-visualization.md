# Hyperbolic Honeycomb Visualization

The "many nested Poincare disks" effect is **not** many separate
hyperbolic planes glued together. It is **one hyperbolic space**
(usually H³) shown in a conformal model (Poincare ball), where:

- Geodesic planes appear as Euclidean spheres orthogonal to the boundary
- Polyhedral cell faces lie in those planes
- When a face (or cell) is ideal/hyperideal, it intersects the boundary
  sphere and creates a circle
- Iterating the symmetry group produces infinitely many such circles
  accumulating to a fractal limit set

This is the visualization approach in Nelson and Segerman's work on
hyperbolic honeycombs.

## 1. Why a Single Poincare Disk Contains "Infinitely Many Disks"

### Poincare Disk (2D) Reminder

In H² (hyperbolic plane), the Poincare disk model:

- Points: x in R² with ||x|| < 1
- Geodesics: arcs of circles orthogonal to the unit circle boundary
- Hyperbolic isometries: Mobius transforms preserving the disk

Even a plain {7,3} tiling produces smaller heptagons near the boundary
because the model compresses lengths exponentially toward ||x|| = 1.

But the "nested disks" effect means you're looking at a **3D honeycomb
{p,q,r} in H³** and seeing its structure on the ideal boundary.

### Poincare Ball (3D) is the Key

For H³, the Poincare ball model:

- Points: x in R³ with ||x|| < 1
- Geodesic planes: Euclidean spheres (or planes) meeting the unit sphere
  orthogonally
- Hyperbolic isometries: conformal maps of the ball (3D Mobius
  transformations)

**Critical fact:**

> A hyperbolic plane in H³ hits the boundary sphere S² in a circle.

When a honeycomb cell face approaches the boundary, you see a circle on
the boundary. When infinitely many faces approach under group
symmetries, you see an infinite circle packing with fractal
accumulation.

Nelson and Segerman visualize honeycombs both "inside the Poincare ball"
and as "sphere packings on the ideal boundary."

## 2. What the Big Circles and Curved Triangles Are

The white shapes bounded by circular arcs are images of faces (or
bisector planes) in the conformal model:

- In the Poincare ball, a fundamental region is bounded by geodesic
  planes
- Each bounding geodesic plane appears as a sphere orthogonal to the
  boundary
- When projected to 2D (or sliced), each sphere becomes a circle arc

The white "curvilinear triangles" are what a **Coxeter simplex** (a
fundamental domain for a reflection group) looks like after conformal
projection.

## 3. Group Theory: Coxeter Reflections and Schlafli {p,q,r}

### What {p,q,r} Means

A Schlafli symbol {p,q,r} denotes a 3D honeycomb:

- Each cell is a regular polyhedron {p,q}
- r such cells meet around each edge

Many hyperbolic {p,q,r} are not compact. They can have:

- **Ideal vertices** (touch boundary)
- **Hyperideal vertices/cells** (extend outside the boundary sphere)

### Coxeter Group Viewpoint

Regular honeycombs correspond to Coxeter groups generated by reflections
in faces of a simplex.

Computationally, you only need:

1. The mirrors (geodesic planes) of a fundamental simplex
2. Reflection matrices that generate the group
3. A way to enumerate group elements up to some depth

Everything else is orbit generation.

**Key bridge to sphere inversion fractals:** Reflection in a geodesic
plane in H³ corresponds (on the boundary) to inversion in a sphere or
circle.

The "nested disks" are what you get applying a reflection group to a few
initial boundary circles.

## 4. Two Visual Layers

### Layer A: Honeycomb Skeleton Inside H³

The actual 3D tiling in the Poincare ball interior:

- Cells are hyperbolic polyhedra
- Faces lie on geodesic planes
- Edges are arcs orthogonal to boundary

Render by building a mesh of cells near the origin, then project to
Euclidean space via Poincare model.

### Layer B: Boundary Sphere Packing and Limit Set

The infinite circle packing on ideal boundary S² (or its stereographic
projection):

- Circles are boundaries of disks, images under reflection group
- Complement is the limit set (fractal boundary accumulation)

"Infinite Poincare disks nested into one outer disk" is Layer B: you see
boundary circles, and inside each you see further structure because the
group maps disks into disks.

## 5. The Computational Pipeline

### Method 1: Explicit Circle/Sphere Orbit Generation

"Geometric object iteration" approach.

**Inputs:**

1. Choose Coxeter simplex for honeycomb {p,q,r}
2. Derive mirror planes in H³ (geodesic planes)
3. Convert each mirror to an inversion sphere acting on the boundary

**Core operation:** Reflection in a hyperbolic plane = inversion in the
boundary circle

**Algorithm:**

```
1. Start with seed boundary spheres/circles (mirror circles or cell faces)
2. Maintain a queue of circles
3. Pop a circle, apply each generator (reflection/inversion), get new circles
4. Deduplicate (epsilon in center and radius)
5. Stop when radius < pixel threshold or recursion depth reached
6. Draw circles from large to small for layered packing
```

**Why fractal:** Group is infinite and discrete, circles shrink
exponentially with word length. Any fixed resolution contains many
nesting levels.

### Method 2: Per-Pixel "Folding" into Fundamental Domain

"Shader friendly" approach - smooth region coloring plus sharp fractal
boundaries.

**Setup:**

- Render boundary sphere S² (2D parameterized) or disk via stereographic
  projection
- Store mirror spheres/planes defining the fundamental simplex

**Per-pixel loop:**

```glsl
for each pixel:
    p = convert pixel to point on boundary sphere or disk

    for i = 0 to N:
        for each mirror:
            if p is on "wrong side" of mirror:
                reflect p across mirror (or invert in circle)
                count++
                record which mirror

        if no reflection applied:
            break  // inside fundamental domain

    color = f(count, lastMirror, distanceToNearestMirror)
```

This produces:

- Smooth basins (few reflections)
- Intricate boundaries (many reflections)
- "Nested disks" automatically (mirror circles being iterated)

## 6. How to Make it 3D

Three distinct meanings:

### 3D-A: Render Actual Honeycomb Cells in H³

Most literal approach.

**Pipeline:**

1. Work in hyperboloid model (x in R^{3,1} where <x,x> = -1)
2. Use reflection matrices in O(3,1) (numerically stable)
3. Generate nearby cells by BFS group enumeration
4. For each cell face, sample points on hyperbolic plane, triangulate
5. Map to Poincare ball: `poincare(x_spatial, x_0) = x_spatial / (1 + x_0)`
6. Render meshes in WebGL/Three.js

### 3D-B: Raymarch "Mirror Field" (Fractal) Inside Ball

Closer to "cave architecture" vibe.

Define distance-like function to nearest mirror plane in hyperbolic
space, then raymarch with repeated folding:

- March in Euclidean space inside Poincare ball
- Convert sample point to hyperbolic coordinates
- Fold point into fundamental domain via reflections
- Evaluate distance to boundary surfaces of fundamental polyhedron
- Step forward

Gives volumetric fractal cavern vibes - raymarching repeated polyhedral
structure in curved metric.

### 3D-C: Keep Fractal on Boundary Sphere, Shade Like Sphere

"Looks 3D" version.

Compute boundary packing (2D), map onto sphere with:

- Stereographic projection, or
- Direct parameterization of S²

Add lighting as if texture lives on 3D sphere.

Visually 3D but geometrically "the boundary at infinity."

## 7. Concrete Mental Model

1. Pick hyperbolic simplex (curved tetrahedron) with dihedral angles
   encoding {p,q,r}
2. Reflect it across faces to tile H³ (Coxeter group)
3. Look at boundary sphere of Poincare ball
4. Each reflecting face hits boundary as a circle
5. Reflecting again produces more circles
6. Infinite collection accumulates to fractal limit set
7. Stereographic projection shows "disks inside disks inside disks"

**That is one space, one group, one boundary.** The "many disks" are
repeated images of a small set of circles under the group.

## 9. Implementation Notes

### For {5,3,4} Dodecahedral Honeycomb

Need to derive the 4 mirror planes of the fundamental Coxeter simplex:

- Angles: pi/5, pi/3, pi/4, pi/2, pi/2, pi/2 (from Coxeter diagram)
- Convert to sphere centers/radii for boundary inversions
- Use Gram matrix to compute exact positions

### The Folding Test

For each mirror, test which side of the plane the point is on:

```glsl
// For plane with normal n and offset d
float side = dot(p, n) - d;
if (side < 0.0) {
    p = p - 2.0 * side * n;  // Reflect
    count++;
}
```

For sphere inversion on boundary:

```glsl
vec3 d = p - center;
float d2 = dot(d, d);
if (d2 < radius * radius) {
    p = center + d * (radius * radius / d2);
    count++;
}
```
