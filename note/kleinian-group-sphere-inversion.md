# Kleinian Group Sphere Inversion Fractals

Conformal fractals generated by sphere inversions, from the theory of
Mobius transformations, Kleinian groups, and hyperbolic geometry.
Rendered by iterating geometric reflections in circles or spheres and
visualizing the resulting limit set on a sphere.

## 1. The Core Geometry: Inversion in Circles and Spheres

The fundamental operation is **inversion**.

### Circle inversion in 2D

Given a circle with center C and radius R, inversion of a point P
produces a new point P' such that:

```
|CP| * |CP'| = R^2
```

and P, C, and P' lie on the same line.

In complex coordinates (after translating so the circle center is at the
origin):

```
p' = (R^2 / |p|^2) * p
```

Key properties:

- Lines and circles map to lines or circles
- Angles are preserved (conformal map)
- The inside and outside of the circle are swapped

So inversion behaves like a geometric mirror, but in a circle instead of
a line.

### Sphere inversion in 3D

Same idea in 3D. For a sphere with center C and radius R:

```
|CP| * |CP'| = R^2
```

and P' lies on the ray from C through P.

Planes and spheres map to planes or spheres. Angles are preserved. This
is the 3D analogue.

These inversions are the building blocks of the transformation group
that generates the fractal.

## 2. Mobius Transformations and Groups

In the plane plus point at infinity, every composition of inversions,
reflections, rotations, and translations can be written as a Mobius
transformation:

```
z' = (az + b) / (cz + d)
```

with complex coefficients and ad - bc != 0.

Geometrically, these are exactly the conformal maps that send circles
and lines to circles and lines.

When you choose a small set of such transformations and allow all
compositions of them, you get a discrete group of Mobius
transformations. In 3D, these generalize to conformal transformations of
the sphere.

Two important classes:

- **Schottky groups**
- **Kleinian groups**

The hyperbolic honeycomb images are typical of a limit set of a Kleinian
or Schottky group generated by inversions in several spheres.

## 3. Fundamental Domains and Group Action

Start with a small number of spheres that define inversion mirrors.
Think of each sphere as a mirror, but with inversion instead of
reflection.

The space is divided into regions:

- A **fundamental domain** is a region of space that contains exactly
  one representative of each orbit of the group action.
- Applying inversions repeatedly maps any point into infinitely many
  copies of that domain.

Smooth regions correspond to points that settle into some stable region
of this group action. The dense lace of circles is where infinitely many
group images accumulate.

## 4. The Limit Set

The most important concept: the **limit set**.

Given a discrete group of Mobius transformations, take any point and
apply all possible compositions of the generators. The set of
accumulation points of these orbits is called the limit set.

Properties of the limit set:

- It is typically fractal
- It is made of circles, arcs, and infinitely nested structure
- It has self-similarity from the group structure

The intricate web in honeycomb images is the limit set. The smooth
regions are complementary domains where points escape to different
basins under the group action.

This is analogous to how the Mandelbrot set is the boundary between
different dynamical behaviors. Here the boundary is defined by inversion
dynamics instead of polynomials.

## 5. Relation to Hyperbolic Geometry

These Mobius groups are not just arbitrary. Many of them act as
isometries of hyperbolic space.

In the Poincare ball model of hyperbolic 3-space:

- The interior of a ball represents hyperbolic space
- Mobius transformations that preserve the ball correspond to hyperbolic
  isometries

The limit set of a Kleinian group often lives on the boundary sphere of
hyperbolic space. So although the image looks spherical, the natural
geometry behind it is hyperbolic 3-space, and the fractal lies on its
boundary at infinity.

**Key insight**: There is a deep hyperbolic connection, but this is not
a spherical tiling. It is a hyperbolic group acting on the boundary
sphere.

## 6. Why It Is Drawn on a Sphere

Two main approaches:

### Approach A: Compute in the plane, map to sphere

1. Work in the complex plane using circle inversions
2. Compute the fractal in 2D
3. Use inverse stereographic projection to map the plane to a sphere

Stereographic projection preserves circles and angles, so the circular
structure remains circular on the sphere.

### Approach B: Work directly with sphere inversions in 3D

1. Define several spheres in 3D that serve as inversion mirrors
2. For each ray direction from the camera, apply repeated inversions in
   those spheres
3. The sphere surface becomes the natural canvas, and the fractal
   appears directly on it

Either way, the sphere is a conformal stage for the limit set.

## 7. How It Is Rendered: The Iterated Inversion Algorithm

A typical shader or ray-based renderer:

### Step 1: Define inversion spheres

Choose a set of spheres S1, S2, S3, etc. Their positions and radii
determine the group and the resulting fractal.

### Step 2: For each pixel, get a point on the sphere

If rendering a sphere, shoot a ray and find its intersection point P on
the sphere surface. That P becomes the initial point for the dynamical
system.

### Step 3: Iteratively fold the point

Repeat for a fixed number of steps:

```
for each inversion sphere Si:
    if P lies inside Si:
        P = invert P in Si
        record that an inversion happened
        continue looping
```

This is like folding space back into a fundamental region, just as in
hyperbolic reflection tilings.

### Step 4: Measure dynamical data

Track values such as:

- Number of inversions
- Which sphere was last used
- Distance to sphere boundaries
- Rate of convergence

These values determine the color.

### Step 5: Coloring

Common choices:

- Smooth regions get soft gradients
- Points near the limit set get high iteration counts and detailed
  coloring
- Curvature shading is added by treating the sphere surface as 3D
  geometry

That produces the glowing fractal web and smooth bulging regions.

## 8. Why the Structure Is Fractal

The fractality comes from:

- Nonlinear inversions
- Infinite compositions of transformations
- Accumulation of group images at the limit set

At every scale, smaller circles appear inside larger ones, because group
elements of longer and longer word length act at smaller and smaller
scales. This is true self-similarity, not just visual repetition.

## 9. Summary

| Aspect    | Description                                     |
| --------- | ----------------------------------------------- |
| Geometry  | Circle and sphere inversion, conformal maps     |
| Algebra   | Discrete groups of Mobius transformations       |
| Dynamics  | Iterated action of the group on points          |
| Fractal   | Limit set where orbits accumulate               |
| Rendering | Iterative inversion per pixel + sphere mapping  |

**Conclusion**: The image is best understood as a Kleinian group limit
set rendered conformally on a sphere, deeply tied to hyperbolic
geometry, but not a spherical tiling in the classical sense.

## 10. Pseudocode for Sphere Inversion Fractal Shader

```glsl
// Define inversion spheres
struct Sphere {
    vec3 center;
    float radius;
};

// Invert point p in sphere s
vec3 invertInSphere(vec3 p, Sphere s) {
    vec3 d = p - s.center;
    float d2 = dot(d, d);
    float r2 = s.radius * s.radius;
    return s.center + d * (r2 / d2);
}

// Check if point is inside sphere
bool insideSphere(vec3 p, Sphere s) {
    vec3 d = p - s.center;
    return dot(d, d) < s.radius * s.radius;
}

// Main iteration
float iterateFractal(vec3 p, Sphere[4] spheres, int maxIter) {
    int count = 0;

    for (int i = 0; i < maxIter; i++) {
        bool folded = false;

        for (int j = 0; j < 4; j++) {
            if (insideSphere(p, spheres[j])) {
                p = invertInSphere(p, spheres[j]);
                count++;
                folded = true;
            }
        }

        if (!folded) break;
    }

    return float(count) / float(maxIter);
}
```
